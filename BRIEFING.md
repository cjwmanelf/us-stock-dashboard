# 모두리치 AI 브리핑 — local implementation

Run `npm ci`, configure `.env.local` from `.env.briefing.example`, then `npm run dev` and open `/briefing`. The existing Supabase login is required. Telemetry implementation is included under `src/lib/briefing/telemetry` by the telemetry worker. No deployment or remote data mutations were performed.

POST `/api/briefing` accepts JSON `{ticker,question?}` and a same-origin browser session cookie. Supabase `getUser()` verifies identity. The API never accepts a user ID, reads holdings, stores conversations, or returns another user's data. Public `getFeed([ticker])` metadata is reused. Responses include answer, source IDs/URLs/dates, asOf, status, version and traceId. A server-signed feedbackToken is present only when its separate signing secret is configured.

Limitations: no article bodies, live prices or completeness guarantee. Empty feeds cannot distinguish upstream outage from absence. LLM output must contain recognized source IDs; semantic entailment still requires evaluation. Unconfigured/failed LLM returns explicit unavailable status and available sources, never fabricated success. OpenAI-compatible provider uses HTTPS, no redirects, 15-second timeout, 1000 output-token budget and 64KiB response bound; not every compatible provider supports the chosen JSON/token options. No real model call has been verified without credentials.

Limits: 4096 request bytes, 500 question characters, one validated ticker, 12 sources, five requests per minute/user, two simultaneous requests/process. Rate limits are process-local and reset on restart; horizontally deployed service needs shared durable rate limiting and edge ingress limits before public rollout. Feed calls have existing five-second individual timeouts (SEC two sequential calls). Authentication has a five-second wait cap. Request-body reads have a five-second deadline. No session or answer caching is enabled.

POST `/api/briefing/feedback` accepts `{traceId,token,feedback: "up"|"down"}` after the same authentication. HMAC signature binds trace, pseudonymous owner and one-hour expiry; no raw user ID is exposed. Stable HMAC score IDs support idempotent retry/update at the telemetry destination. Export disabled/failure returns 503. 202 means export flush completed, not verified ingestion; UI says so. No local-memory ownership dependency remains.

Content capture defaults off. Normal user content is never exported; only independently authorized local synthetic evaluation traffic can use both content opt-ins. Telemetry sanitization may alter evaluation evidence; use the independent private input snapshot for evidence checks. Metadata-only traces are not suitable for answer-quality analysis. Environment secrets stay server-side.

Primary references consulted: https://nextjs.org/docs/app/api-reference/file-conventions/route ; installed Next 16.2.10 `node_modules/next/dist/docs` route/turbopack guides; https://supabase.com/docs/guides/auth/server-side/nextjs ; https://platform.openai.com/docs/api-reference/chat/create .

Evaluation capture requires BRIEFING_EVAL_MODE=true in an isolated loopback-only local instance used only with synthetic questions and public evidence, plus both content switches. Never enable evaluation mode for production user traffic. Normal sanitized-user content is deliberately not exported by the adapter. A frozen evidenceSnapshot (ticker, question, asOf, sources) is assembled before generation and carried to opt-in traces for private paired replay; there is no production replay endpoint.

Optional pre-generation evidence sink: set BRIEFING_EVAL_SNAPSHOT_DIR to the absolute repo/.briefing-eval path. It writes original supplied evidence, feed-attributed source ticker, request, asOf and traceId before model invocation (no credentials or user IDs); local collector adds caseId/split and joins the unchanged response. Maximum 1000 files, 32KiB each; failures return EVAL_SNAPSHOT_FAILED and stop model invocation. The folder is ignored. generateBriefingFromEvidence is a server-only harness hook for paired frozen-evidence runs, never a public replay endpoint. Langfuse content may be redacted/truncated and must not replace these independent input artifacts.

Evaluation isolation enforcement: flags alone never enable capture. API must verify the normal Supabase session, match BRIEFING_EVAL_USER_ID, receive an independently configured >=32-character BRIEFING_EVAL_REQUEST_TOKEN in x-briefing-eval-token (timing-safe check), and use an HTTP loopback hostname. Any VERCEL or VERCEL_ENV environment disables capture entirely, including preview. Run the local server bound to 127.0.0.1; never expose this evaluation instance to network traffic. Ordinary UI requests carry no evaluation token and cannot capture. The internal authorization object is required by both generation and snapshot sink; pure replay defaults to capture disabled.

Validation: npm ci completed; npm run build (Next 16.2.10) and focused ESLint passed; scripts/briefing-check.cjs passed input/body/rate/HMAC/expiry and evaluation isolation checks. Local built-server smoke check passed /briefing HTML, cross-origin 403, unconfigured-auth 503 and no-store headers. No authenticated real Supabase session, real LLM completion, live Langfuse ingestion, or production deployment was verified. npm install reports 18 install-reported dependency audit findings (9 moderate, 8 high, 1 critical); baseline attribution is unverified, and remediation was not mixed into this feature.
